Rehearse once on the actual computer before presenting. Use `START_HERE.md` to launch. Use a normal/private browser window or separate profiles for student and teacher; ordinary tabs share the same login cookie. No screenshots or hardware/provider success is implied by this guide.

1. Introduce this as a tested development build. Identify synthetic people and starting mastery values; explain which AI features are offline excerpts versus configured live providers.
2. Student Saim / 23F-1234: inspect BFS 90%, DFS 85%, Heuristics 48%, A* 39% on a fresh database. These are seeded priors, not fabricated observed results.
3. Tutor: ask “Explain A* in Roman Urdu according to Lecture 6.” Show the retrieved bilingual excerpt and actual Lecture_6.pptx / Slide 18 reference. Offline mode does not generate a new translation.
4. Inspect A*, UCS and Heuristics in the knowledge map and prerequisite-first path. Start adaptive practice. Answer incorrectly, inspect the explanation, possible misconception and calculated mastery change; no target percentage is forced.
5. Complete practice and open My progress. Show the six readiness factors, evidence gaps, saved revisions and mastery estimates.
6. Save a study plan for next week with one hour per selected day. Complete/skip tasks, reopen the page and reschedule. Explain that unschedulable work remains visible and time budgets are not silently exceeded.
7. Start a two-question A* viva. For reliable offline presentation, **type** an answer and submit. Show teacher-review status with no invented AI score. Teacher → Viva review → confirm score/feedback. Student → saved session → see the confirmed result and updated learning evidence.
8. Run a short timed mock, answer a question, then finish early. Show delayed exam feedback, unanswered questions, marks and topic/CLO result breakdown. Resume its saved results.
9. Upload a private text file in Materials and attach it to an assignment. Teacher → Assignments → download only that submitted attachment and grade it. Student → notification/assignment → read the feedback. Other private uploads remain inaccessible to teachers.
10. Teacher directory: search 23F-1234, inspect mastery/readiness/viva/Bloom, add a private note, inspect class analytics and export CSV. No public student ranking is displayed.
11. Teacher: draft and approve an MCQ; it becomes eligible for assessment. In Research checks, explain descriptive metrics and run a labelled lexical retrieval example using an actual chunk ID from Materials.
12. Administrator: inspect users, course teaching assignments and configuration presence. Do not expose `.env` or private invitation values on a projector.
13. Demonstrate BFS/DFS/UCS/A* steps, then show tests and `FINAL_STATUS.md`. Explain pending live-provider, real-device, deployment and research-validation work.

Microphone speech and generated responses are optional for this rehearsal. If you intend to demonstrate them, configure and test your own provider and actual browser first; keep typed/extractive fallbacks available.
